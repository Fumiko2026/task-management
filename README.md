# task-management(アプリの名前: Kokuban)

「Kokuban(黒板)」は、リストにカードを貼るように、タスクを管理するアプリです。画面は、緑の黒板に白いカードを貼る見た目です。

Trello 風のカンバン形式タスク管理アプリです。スマートフォンで、各自が自分のタスクを管理します。

> WEBスクールの課題として作成しています。詳しい要件は [requirements.md](requirements.md) を参照してください。

---

## 1. このアプリの目的

次の3つを実現します。

| やりたいこと | 具体的には |
|---|---|
| 締め切りを守る | 期限が近いと色とアイコンで知らせ、通知でリマインドする |
| 担当者がわかる | どのタスクも「誰が」やるかが一目でわかる |
| 過程と完了がわかる | 準備の手順(チェックリスト)と、終わったことが見える |

## 2. 使う人

- 一般の会社員

**個人利用**です。スマートフォンで、各自が自分のタスクを管理します。チームでの共有は行いません。

## 3. 基本のしくみ(Trello 風)

```
ボード(プロジェクト全体)
 ├─ リスト「未着手」 ── カード、カード
 ├─ リスト「進行中」 ── カード
 └─ リスト「完了」   ── カード(いつも、いちばん右)
```

- **ボード**: プロジェクトや授業・仕事のまとまり
- **リスト**: 状態を表す列(未着手 / 進行中 / 完了)。完了は、いつも、いちばん右
- **カード**: 1つのタスク。ドラッグで、リストの間・リストの中を入れ替えられる(スマホは長押し)

## 4. カードに持たせる情報

| 項目 | 内容 |
|---|---|
| 担当者 | 原則1名。決まっていないカードは警告表示 |
| 締め切り | 日付と時刻。「通常 / 期限が近い / 期限超過 / 完了」を色とアイコンで区別 |
| 準備の過程 | チェックリスト。カード一覧に進み具合(例: 3/5)を表示 |
| 完了 | チェックを付けると完了。いつ終わったかも記録 |

## 6. おまけ機能: 「実績の記録」

仕事上の信用を支え、自信につなげる機能です。

「スタンプが飛び出す」のような派手な演出は、人によっては子供っぽく感じられます。大人の利用者向けに、**控えめな演出と、実際の数字による裏付け**を組み合わせます。

| 機能 | 内容 | 印象 |
|---|---|---|
| 完了の演出 | チェックを付けると、チェックマークがなめらかに描かれ、軽く振動する | 控えめで上品 |
| 期限内完了率 | 「今月、期限内に完了した割合 92%」を表示 | 数字で信用を示せる |
| 連続達成 | 「期限を守った日が7日連続」 | 続ける励みになる |
| 完了の履歴 | 「いつ・何を終えたか」を一覧で見られる | 振り返りや面談に使える |

- 演出は設定でオフにできます(職場で使う人にも配慮)。
- 数字は自分だけが見られる設定を基本にします。

## 11. バックエンドの動かし方

DB(PostgreSQL)に接続でき、アプリの起動時にテーブル(6 つ)が自動で作られます。取得(Read)の API は、DB のデータを返します。テーブルの内容は [docs/table-definition.md](docs/table-definition.md) を参照してください。

### 必要なもの
- Java 21(`java -version` で 21 と表示されること)
- Maven は別に入れなくてよい(`backend/mvnw` が自動で用意する)
- Docker Desktop(PostgreSQL を動かすため。起動しておく)

### DB(PostgreSQL)の起動
初回だけ、設定ファイルを作ります。`.env` の `POSTGRES_PASSWORD` は自分用の値に変えてください(`.env` は GitHub に上がりません)。
```
cp .env.example .env
```
起動と停止は、プロジェクトの直下で行います。
```
docker compose up -d      # 起動(STATUS が healthy になれば準備完了。docker compose ps で確認)
docker compose down       # 停止(データは残る)
```
データを消して最初からやり直すときだけ `docker compose down -v` を使います。

DB のポート(5432)は、パソコンの中(127.0.0.1)だけに公開しています。同じ Wi-Fi の端末からは、DB につながりません。

### 起動
プロジェクトの直下で、スクリプトを実行します。DB のパスワードは `.env` から自動で読むので、設定は要りません。DB(Docker)が動いていないときは、やり方を案内して止まります。
```
./dev.sh run
```
| コマンド | 内容 |
|---|---|
| `./dev.sh run` | アプリを起動(テストデータは入れない) |
| `./dev.sh seed` | テストデータを入れて、アプリを起動 |
| `./dev.sh test` | 自動テストを実行 |

> スクリプトを使わずに、手で起動することもできます。`cd backend` → `export DB_PASSWORD=.env に書いたパスワード` → `./mvnw spring-boot:run`。`export` は、ターミナルを新しく開くたびに必要です。

初回は部品のダウンロードで数分かかります。`Started TaskManagementApplication` と表示されれば起動しています。止めるときは、ターミナルで `control` + `c`。

起動のたびに、`backend/src/main/resources/db/schema.sql` が実行され、テーブルが無ければ作られます(あるテーブルは変わりません)。

### テストデータを入れて起動
確認用のテストデータ(ボード 1 つ、リスト 3 つ、カード 5 枚、チェックリスト 5 項目)を DB に入れるには、`seed` を付けて起動します。
```
./dev.sh seed
```
- 通常の起動(`./dev.sh run`)では、テストデータは入りません。
- 起動のたびに、デモ利用者(`demo@example.com`)のデータを作り直します。何度起動しても同じ結果になります(途中で変えたデータは元に戻ります)。
- 中身は [backend/src/main/resources/db/seed.sql](backend/src/main/resources/db/seed.sql) です。期限は「いま」からの相対なので、いつ動かしても、超過・もうすぐ・通常・完了の状態がそろって見えます。

### 動作の確認
| 確認 | コマンド | 結果 |
|---|---|---|
| 起動と DB 接続の確認 | `curl http://localhost:8080/actuator/health` | `{"status":"UP"}`(DB がつながっていないと `DOWN`) |
| ボードの取得 | `curl http://localhost:8080/api/board` | ボードのデータ(JSON)。ボードが無いときは 404 |
| カード 1 枚の取得 | `curl http://localhost:8080/api/cards/1` | カードの詳細(チェックリストつき)。無いときは 404 |
| 自分のタスク | `curl http://localhost:8080/api/tasks` | 未完了のカードを、期限が近い順に(期限なしは最後) |
| **カードの作成** | 下の「カードを作る(POST)」を参照 | 201 と、作ったカード |

### カードを削除する(DELETE /api/cards/{id})
カードを、**DB から本当に消します(物理削除)。元に戻せません。**
```
curl -i -X DELETE http://localhost:8080/api/cards/1
```
- 消せると **204**(中身なし)を返します。
- そのカードの**チェックリストも、一緒に消えます**(DB の仕組みで、自動で消えます)。
- 同じリストに残ったカードの並び順は、**1,2,3… に振り直されます**(欠番はできません)。ほかのリストやカードは、変わりません。
- カードが無いときは **404**(`カードが見つかりません(id=…)`)です。同じカードを 2 回消すと、2 回目は 404 になります。
- DB から消えたかどうかは、次のように、DB を直接見て確かめられます(`.env` の値を使います)。
  ```
  set -a; . ./.env; set +a
  docker exec task-management-db psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT id, title FROM cards"
  ```
- 画面から削除するボタン(削除の前に確認を出す)は、まだありません。

### カードの期限を変える(PATCH /api/cards/{id})
送った項目だけを変えます(部分更新)。いま変えられるのは、**期限(`dueAt`)だけ**です。日時は、**時差つき**(`+09:00` や `Z`)で送ります。`null` を送ると、期限が消えます。
```
# 期限を設定する
curl -i -X PATCH http://localhost:8080/api/cards/1 \
  -H 'Content-Type: application/json' \
  -d '{"dueAt": "2026-11-10T18:00:00+09:00"}'

# 期限を消す
curl -i -X PATCH http://localhost:8080/api/cards/1 \
  -H 'Content-Type: application/json' \
  -d '{"dueAt": null}'
```
- 変えられると **200** で、更新後のカードを返します(期限の状態 `dueStatus` も、新しい値です。日時は、日本時間の時差にそろいます)。
- **リスト、並び順、完了日時は、変わりません。** 完了済みのカードの期限も変えられます(完了のままです)。
- **優先度の専用の項目は、ありません。** 優先度は、リストの中の上下の位置(上ほど高い)で表します。変えるときは、カードをドラッグで上下に動かします。
- 次のときは、日本語の理由つきで断ります。

| 状況 | 結果 | 理由の例 |
|---|---|---|
| カードが無い | 404 | カードが見つかりません(id=…) |
| 本文が空(`{}`) | 400 | 変更する項目を指定してください |
| `dueAt` 以外の項目 | 400 | 更新できない項目です: title(いまは dueAt だけ) |
| `dueAt` が、日時の文字でも null でもない | 400 | dueAt は、日時の文字、または null で指定してください |
| 日時の形が正しくない・時差が無い | 400 | 期限の日時の形が正しくありません。時差つきで指定してください… |
| 年が 2000〜2100 の範囲外 | 400 | 期限の日付が範囲外です(2000〜2100年) |
| 本文が JSON として読めない | 400 | 送られた内容を読み取れません… |

### カードを完了にする・未完了に戻す(PATCH /api/cards/{id}/complete)
画面の完了マーク(○/✔)に当たる API です。
```
# 完了にする
curl -i -X PATCH http://localhost:8080/api/cards/1/complete \
  -H 'Content-Type: application/json' \
  -d '{"completed": true}'

# 未完了に戻す
curl -i -X PATCH http://localhost:8080/api/cards/1/complete \
  -H 'Content-Type: application/json' \
  -d '{"completed": false}'
```
- **完了にする(`true`):** カードを「完了」リストの**いちばん上**へ移し、完了日時を記録します。**完了する前にいたリストを、覚えます**(`cards.completed_from_list_id`)。
- **未完了に戻す(`false`):** 完了前にいたリストの**最後**へ戻し、完了日時と、覚えていた記録を消します。覚えていない(ドラッグで入れていない、など)・そのリストが消えた・別のボードのときは、**いちばん左の開いたリスト**(いまは「未着手」)へ戻します。
- 入れる位置を決めたいときは、`"position": 2`(1 から)も送れます。
- ドラッグ(`move`)で「完了」へ入れたときも、完了前のリストを覚えます。あとで `complete` の `false` で、そのリストへ戻せます。
- すでにその状態のとき(完了済みに `true`、未完了に `false`)は、何も変えずに、200 でそのカードを返します。
- 200 で、更新後のカードを返します。並び順は、移した先も、元のリストも、1,2,3… に振り直されます。
- 次のときは、日本語の理由つきで断ります。

| 状況 | 結果 | 理由の例 |
|---|---|---|
| カードが無い | 404 | カードが見つかりません(id=…) |
| `completed` が無い | 400 | completed を、true か false で指定してください |
| `position` が 1 未満 | 400 | 位置は1以上で指定してください |
| `completed` が真偽値でない・本文が読めない | 400 | 送られた内容を読み取れません… |

- DB の `cards` に、`completed_from_list_id` の列が足されます(アプリの起動時に、自動で足されます。**今の DB のデータは、消えません**)。
- 画面の完了マーク(○/✔)は、まだ押せません(次の作業です)。

### チェックリストに項目を足す(POST /api/cards/{id}/checklist-items)
`curl` で、カードのチェックリストの最後に、項目を足します(`{id}` は、カードの id)。
```
curl -i -X POST http://localhost:8080/api/cards/1/checklist-items \
  -H 'Content-Type: application/json' \
  -d '{"text": "見積書を送る"}'
```
- **201 Created と、更新後のカード(`checklistTotal` の数も新しい値)**を返します。足した項目は、**未完了で、いちばん最後**に入ります。
- 前後の空白(全角も)は取り除いて保存します。1〜100 文字です。カードの期限・完了の状態は、変えません。

| 状況 | 結果 | 理由の例 |
|---|---|---|
| `text` が無い・空・空白だけ | 400 | 項目を入力してください |
| 101 文字以上 | 400 | 項目は100文字までです |
| 本文が読めない・`text` が文字でない | 400 | 送られた内容を読み取れません… |
| カードが無い | 404 | カードが見つかりません(id=…) |

### チェックリストの項目を完了にする・未完了に戻す(PATCH /api/checklist-items/{id})
`curl` で、項目の完了を切り替えます(`{id}` は、`GET /api/board` の `cards[].checklist[].id`)。
```
curl -i -X PATCH http://localhost:8080/api/checklist-items/1 \
  -H 'Content-Type: application/json' \
  -d '{"done": true}'
```
- `{"done": true}` で完了、`{"done": false}` で未完了に戻します。**200 と、その項目があるカード(更新後。`checklistDone` の数も新しい値)**を返します。すでにその状態なら、何も変えずに 200 です(二重のタップに強い形)。
- カードの期限・完了の状態・項目の順番は、変えません。

| 状況 | 結果 | 理由の例 |
|---|---|---|
| `done` が無い・null | 400 | done を、true か false で指定してください |
| `done` が真偽値でない・本文が読めない | 400 | 送られた内容を読み取れません… |
| 項目が無い | 404 | チェックリストの項目が見つかりません(id=…) |

### カードを動かす(PATCH /api/cards/{id}/move)
カードを、別のリストや、同じリストの別の位置へ動かします。`position` は、**移した先で何番目に置くか**(1 から)です。省略すると、最後に置きます。
```
curl -i -X PATCH http://localhost:8080/api/cards/1/move \
  -H 'Content-Type: application/json' \
  -d '{"listId": 2, "position": 1}'
```
- 動かせると **200** で、動かしたあとのカードを返します(完了日時と期限の状態は、新しい値です)。
- 移した先と、元のリストの**並び順は、1,2,3… と振り直されます**(欠番はできません)。`position` が大きすぎるときは「最後」に置きます。
- **「完了」のリストへ動かすと、完了日時が記録されます**(すでに完了していれば、そのままです)。**「完了」から出すと、完了日時が消えて、未完了に戻ります**。
- 次のときは、日本語の理由つきで断ります。

| 状況 | 結果 | 理由の例 |
|---|---|---|
| カードが無い / 移し先のリストが無い | 404 | カードが見つかりません(id=…) |
| 別のボードのリスト | 400 | 別のボードのリストには、動かせません |
| `position` が 1 未満 | 400 | 位置は1以上で指定してください |
| `listId` が無い | 400 | 移し先のリストを指定してください |
| 本文が JSON として読めない | 400 | 送られた内容を読み取れません… |

### カードを作る(POST /api/cards)
タイトルだけで作れます。リストの id は、ボードの応答の `lists[].id` で確かめます(「完了」のリストには作れません)。
```
curl -i -X POST http://localhost:8080/api/cards \
  -H 'Content-Type: application/json' \
  -d '{"listId": 3, "title": "請求書を送る"}'
```
- 作れると **201 Created** で、作ったカードを返します(`Location` に、そのカードの取得先が入ります)。
- 作ったカードは、**そのリストの最後**に入ります。担当者は**自分**、期限は**なし**、説明は空です。
- タイトルの前後の空白(全角も)は、取り除いて保存します。
- 次のときは、日本語の理由つきで断ります(`{"message": "..."}`)。

| 状況 | 結果 | 理由の例 |
|---|---|---|
| タイトルが空・空白だけ・無い | 400 | タイトルを入力してください |
| タイトルが 101 文字以上(1〜100 文字) | 400 | タイトルは100文字までです |
| `listId` が無い | 400 | リストを指定してください |
| 「完了」のリスト | 400 | 完了のリストには、カードを追加できません |
| 本文が JSON として読めない | 400 | 送られた内容を読み取れません… |
| 指定のリストが無い | 404 | リストが見つかりません(id=…) |

- **エラーの形は、どの API でも同じです**(`{"message": "日本語の理由"}`、UTF-8)。上の表のほかに、次のときも、この形で返します。

| 状況 | 結果 | 理由の例 |
|---|---|---|
| URL の中の id が数字でない(例: `/api/cards/abc`) | 400 | URL の中の「id」は、数字で指定してください |
| 存在しない URL | 404 | 指定された場所(URL)が見つかりません |
| その URL では使えない操作(例: `DELETE /api/board`) | 405 | この URL では、その操作(メソッド)は使えません |
| JSON 以外の形式で送った | 415 | 送られた形式に対応していません… |
| 想定外の故障 | 500 | サーバーで問題が起きました…(内部の事情は返さず、サーバーのログにだけ残します) |

- カードの id は、ボードの応答の中の `cards[].id` で確かめられます(1 とは限りません)。
- ブラウザで `http://localhost:8080/api/board` を開いても見られます。
- **ログインはまだ無いため、ボードは「id が最小の 1 つ」を返します。** ログインを作る段階で、ログインした利用者のデータだけに絞ります。

### テスト
テストは実際の DB につないで確かめますが、**開発用の DB とは別の、テスト専用の DB**(`<開発用の DB 名>_test`。例: `taskmanagement_test`)を使います。開発のデータは、テストで消えたり変わったりしません。先に DB を起動して(`docker compose up -d`)から実行します。テスト用の DB が無ければ、`./dev.sh test` が自動で作ります。テストで入れたデータは、終わると元に戻ります。
```
./dev.sh test
```

#### 自動テスト(CI)
PR を作る・更新すると、GitHub Actions(`.github/workflows/ci.yml`)が、バックエンドとフロントエンドのテストを自動で実行します。バックエンドは、CI の中に使い捨ての PostgreSQL を立てて `./mvnw test` を、フロントエンドは `npm run lint`・`npm test`・`npm run build` を実行します。PR の画面の「Checks」が緑(成功)になってから、統合します。

### 注意
DB のパスワードなど、秘密の情報は GitHub に上げません。DB をつなぐ段階で、設定ファイルを分けて管理します。

## 12. フロントエンド(画面)の動かし方

React(TypeScript、Vite)で作った画面です。いまは、**ボード画面の表示、カードの追加、カードの入れ替え(ドラッグ)、カードの編集(期限の変更・削除)、完了マーク(○/✔)のタップ**ができます。タイトル・担当者の編集は、まだありません。

### 必要なもの
- Node.js(`node -v` で番号が出ること)。入っていなければ、`brew install node`。
- バックエンドが動いていること(下の手順の 1)。

### 手順(ターミナルを 2 つ使います)
1. 1 つ目のターミナルで、バックエンドを、テストデータつきで起動します。
   ```
   ./dev.sh seed
   ```
2. 2 つ目のターミナルで、画面を起動します。初回は、部品のダウンロードで少し時間がかかります。
   ```
   ./dev.sh front
   ```
3. ブラウザで http://localhost:5173 を開きます。ボード「はじめてのボード」が表示されます。
4. 止めるときは、それぞれのターミナルで `control` + `c`。

### 見え方
- **スマホ:** リストの幅は画面幅の約 45%。横にスクロールして、他のリストを見ます。
- **パソコン(幅 768px 以上):** リストの幅は、画面の幅に合わせて縮みます(最小 180px、最大 280px)。リストが 4 つあっても、横にスクロールしなくても、全部見えます(いまは 3 つ)。広い画面(約 1200px 以上)では、280px のままです。
- 期限は、色に加えて、アイコンと文字でも示します(❗ 超過 / ⏰ もうすぐ / 🕒 通常 / ✔ 完了)。
- 読み込み中は灰色の枠、失敗したときは「読み込めませんでした」と「もう一度試す」、ボードが無いときは「ボードがありません」が出ます。

### 完了マーク(○/✔)を押す
カード左上の **○ を押すと、完了**になります。**✔ を押すと、未完了に戻ります**。押せる範囲は 44×44px 以上です(見た目の大きさは、そのままです)。押しても、カードのドラッグは始まらず、編集ダイアログも開きません。
- **○ を押す(完了にする):** カードが「完了」リストの**いちばん上**へ移り、✔ になります。画面の下に、**「『カード名』を完了にしました [元に戻す]」が 5 秒間**出ます。
  - 「元に戻す」を押すと、**もとのリストの、もとの位置**へ戻ります。5 秒たつと、知らせは消えます。
  - スマホでは、軽く振動します(iPhone では振動しません)。
- **✔ を押す(未完了に戻す):** **完了前にいたリスト**の最後へ戻ります(進行中から完了にしたカードは、進行中へ戻ります)。ドラッグで「完了」へ入れたカードも、入れる前のリストへ戻ります。完了前のリストが分からないカードは、いちばん左のリスト(未着手)へ戻ります。
- **チェックリストが残っているカード**を完了にするときは、先に「**チェックリストが残っています**。まだ終わっていない手順が ○ 件あります。完了にしますか」と確認が出ます(「完了にする」「やめる」)。
- 保存できなかったときは、画面の下に「保存できませんでした。(理由)」が出て、カードは動きません。
- キーボードでは、完了マークにフォーカスして、Enter キー(または Space キー)で押せます。

### カードを編集する(期限の変更・削除)
カードを**押す**(クリック、スマホではタップ。キーボードなら、フォーカスして Enter キー)と、ボードの上に、**編集ダイアログ**が開きます。スマホでは、画面の下から出ます。ドラッグした直後には、開きません。
- **期限を変える:**
  - 「今日」「明日」「来週」を押すと、その日の **18:00** が入ります(「来週」は 7 日後です)。
  - 日付と時刻は、入力欄で選べます(スマホでは、その端末の選択部品が出ます)。
  - 「期限を消す」を押すと、期限をなしにする準備ができます(**「決定」を押すと保存されます**)。
  - **「決定」** で保存します。カードの表示が、すぐ変わります(期限の状態の色・アイコンも変わります)。
  - 過去の日時を選んだときは、「過去の日時です。このままにしますか」と出ます(「このまま保存」か「選び直す」)。
  - 「キャンセル」、Esc キー、暗い背景を押すと、保存せずに閉じます。
- **チェックリストを使う:** カードを押すと開くダイアログの上の方に、「チェックリスト(3/5 完了)」と、項目の一覧が出ます(**すべてのカード**で、この欄が出ます。項目が無いカードは「チェックリストは、まだありません」)。終わった項目は「☑」、まだの項目は「○」です。**項目を押すと、「○」は「☑」(完了)に、「☑」は「○」に戻ります。** 押すと、カード一覧の「3/5」も、すぐ変わります。保存できなかったときは、理由が出て、表示は元のままです。**項目を足す:** チェックリストの下の入力欄に、手順を入れて「追加」(または Enter)を押します。いちばん最後に、「○」の項目として入り、続けて入力できます(100 文字まで。空のままでは押せません)。保存できなかったときは、入力欄のそばに理由が出て、入れた文字は残ります。**項目の文言を変える・消す・並べ替える操作は、まだありません**(次の段階で作ります)。全部の項目を終えても、カードは自動では完了になりません(完了マークを押します)。
- **カードを削除する:** 「このカードを削除」を押すと、確認が出ます。「削除する」を押すと、**DB から本当に消えます(元に戻せません。チェックリストも消えます)**。迷ったときのために、最初のフォーカスは「やめる」に置いてあります。
- 保存や削除に失敗したときは、ダイアログが**開いたまま**、理由が出ます(入力した内容は残ります)。
- **優先度:** 専用の項目はありません。リストの中の上下の位置(上ほど高い)で表します。カードをドラッグして、上下に動かして変えます。

### カードを入れ替える(ドラッグ)
カードを動かして、リストの間・リストの中を入れ替えられます。置いた位置は、保存されます(読み込み直しても残ります)。
- **パソコン(マウス):** カードをつかんで、少し(約 8px)動かすと、持ち上がります。動かしたい場所で、はなします。
- **スマホ(指):** カードを**約 0.5 秒、押さえたまま**にすると、持ち上がります(軽く振動します。iPhone では振動しません)。そのまま指を動かして、はなします。押さえずに指を動かすと、今までどおり、画面のスクロールになります。
- **キーボード:** カードにフォーカスを当てて、Space キーで持ち上げ、矢印キーで動かし、もう一度 Space キーで置きます。Esc キーで取り消します。
- **「完了」へ入れると、自動で完了になります**(✔ が付き、完了日時が記録されます)。**「完了」から出すと、未完了に戻ります**(○ に戻り、期限の状態も元に戻ります)。
- 保存できなかったときは、カードが**元の場所に戻り**、「保存できませんでした。(理由)」が、画面の下に数秒出ます。

### カードを追加する
1. 「未着手」「進行中」の下にある **「＋ カードを追加」** を押すと、その場に入力欄が開きます。
2. タイトルを入れて、**「追加」**(または Enter)を押します。空のままや空白だけでは、押せません。タイトルは 100 文字までです。
3. カードは、そのリストの**最後**に増え、件数も増えます。担当者は「自分」、期限はなしです。詳しい内容は、あとからカード詳細で入れる予定です(まだありません)。
4. **入力欄は開いたまま**なので、続けて追加できます。閉じるときは「キャンセル」か Esc キーです。
5. 保存できなかったときは、理由が出て、入力した文字は残ります。
- 「完了」のリストには、追加ボタンはありません(完了のリストにあるカードは、完了日時が記録されたカードのため)。
- 動作確認で追加したカードは、DB に残ります。`./dev.sh seed` で起動し直すと、デモのデータは作り直されます。

### テスト
```
./dev.sh front-test
```
`frontend/` で、`npm run lint`(書き方の検査)と `npm run build`(型の検査を含む)も実行できます。

### iPhone で見る(試すときだけ)
iPhone のブラウザで、この画面を見られます。パソコンと iPhone を、**同じ Wi-Fi** につないで、次を実行します。
```
./dev.sh seed          # 1 つ目のターミナル(バックエンド。すでに動いていれば、不要)
./dev.sh front-phone   # 2 つ目のターミナル
```
表示された住所(例: `http://192.168.3.82:5173`)を、iPhone の Safari で開きます。初めて起動したときに、「ネットワーク接続を許可しますか」と出たら、「許可」を押してください。
- **ログインが無いため、公開している間は、同じ Wi-Fi の人なら、だれでも、中身を見たり変えたりできます。** 自宅の Wi-Fi で、試す間だけ使ってください。お店や学校などの Wi-Fi では、使わないでください。
- 終わったら `control` + `c` で止めて、ふだんの `./dev.sh front`(パソコンの中だけ)に戻します。
- 公開するのは、画面のサーバー(5173)だけです。**バックエンド(8080)は、パソコンの中だけ**(`127.0.0.1`)で待ち受けるので、iPhone からは、画面のサーバー経由でしか届きません(API を直接は呼べません)。
- iPhone では、カードを約 0.5 秒押さえたままにすると持ち上がります(振動はしません)。

### ポートが使われていたとき
バックエンドは **8080**、フロントエンドは **5173** で動きます。別のポートへは移りません。
`./dev.sh run` / `./dev.sh seed` / `./dev.sh front` は、起動の前に、そのポートを使っているプロセスを**自動で停止**してから、起動します(何を止めたかが表示されます)。
- 例: 前に起動したアプリが、ターミナルを閉じても動き続けているとき。
- 手で止めるとき: `./dev.sh free-port 8080`(バックエンド)、`./dev.sh free-port 5173`(フロントエンド)。
- 止めるのは、この 2 つのポートだけです。DB(5432)は止めません。

### しくみ
- 画面は、`/api/board` を呼んで、ボードのデータを取ります。開発中は、Vite(5173)が、`/api` で始まる通信をバックエンド(8080)へ中継します。そのため、CORS(別の場所からの通信の許可)の設定は要りません。
- API が返すデータの形は、`frontend/src/api/types.ts` にあります。
