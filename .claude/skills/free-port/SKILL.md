# ポートの競合を解消する

このプロジェクトのサーバーは、**標準のポートで動かす**。ポートが使われていたら、**使っているプロセスを必ず停止して**から、標準のポートで起動する。別のポートに変えて逃げてはいけない。

| サーバー | 標準のポート | 起動コマンド |
|---|---|---|
| バックエンド(Spring Boot) | **8080** | `./dev.sh run` / `./dev.sh seed` |
| フロントエンド(Vite) | **5173** | `./dev.sh front` |

フロントエンドは、画面の確認先(`http://localhost:5173`)、バックエンドへの中継先(8080)、README などの案内が、この番号に決まっている。別のポートで動かすと、画面が見られない、API につながらない、という食い違いが起きる。

## 手順

1. **競合を確かめる。** 起動のエラーに、ポート番号と「使用中」が出ていれば競合。次で、使っているプロセスを見る。
   ```
   lsof -nP -iTCP:8080 -iTCP:5173 -sTCP:LISTEN
   ```
2. **停止する。** `./dev.sh run` / `seed` / `front` は、起動の前に、自動でこの停止を行う。手で止めるときは次のコマンド(プロジェクトの直下で実行)。
   ```
   ./dev.sh free-port 8080     # バックエンド
   ./dev.sh free-port 5173     # フロントエンド
   ```
   - 止める前に、何を止めるかが表示される。通常の停止(SIGTERM)を試し、10 秒たっても止まらなければ強制終了(SIGKILL)する。
3. **標準のポートで、もう一度起動する。** 上の表のコマンドを使う。
4. **起動を確かめる。**
   - バックエンド: `curl http://localhost:8080/actuator/health` が `{"status":"UP"}`
   - フロントエンド: `curl -s http://localhost:5173 | grep タスク管理` が出る。`curl http://localhost:5173/api/board` が、バックエンドからの応答を返す
5. **利用者に報告する。** 「ポート ○○ を、△△(プロセス名)が使っていたので止めました」と、**何を止めたか**を、やさしい日本語で伝える。

## 気をつけること(エラーが出ない競合)
IPv4(`*:5173`)と IPv6(`[::1]:5173`)は、別の待ち受けとして扱われる。そのため、**エラーが出ないまま、2 つのサーバーが同じ番号で動いてしまう**ことがある。画面が古い、API の応答が違う、前のバージョンの画面が出る、というときは、`lsof -nP -iTCP:5173 -sTCP:LISTEN` で、使っているプロセスが 2 つ以上ないか確かめ、`./dev.sh free-port` で空けてから起動し直す。

## 守ること
- **別のポートで起動しない。** `--server.port=...`、`--port ...`、`vite.config.ts` や `application.properties` のポートの書き換え、は行わない。
- **止めてよいのは、8080 と 5173 を使っているプロセスだけ。** DB(5432。Docker の `task-management-db`)など、他のポートのプロセスは、この手順では止めない。`scripts/free-port.sh` も、この 2 つ以外のポートは、断る。
  - 5432 が使われていて DB が起動しないときは、止めずに、何が使っているかを調べて(`lsof -nP -iTCP:5432 -sTCP:LISTEN`)、利用者に状況を伝え、どうするか相談する(パソコンに別の PostgreSQL が入っている場合など)。
- **そのポートで待ち受けている(LISTEN)プロセスだけを止める。** `pkill java` や `killall node` のように、名前で広く止めない。
- 止めたのに、まだ使われているとき(別のユーザーのプロセスなど)は、`sudo` で無理に止めず、状況を利用者に伝える。
- 管理者のパスワードを求められたら、利用者のターミナルで実行してもらう。
