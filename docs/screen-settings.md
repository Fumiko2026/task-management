## 1. この画面の役割

アプリの使い方を自分に合わせる。通知の受け取り方、文字の大きさ、演出、依頼先の名前、削除したカードの復元、データの書き出し、アカウントの管理を行う。

## 3. S-06a 通知設定

### 画面イメージ
```
┌──────────────────────────────┐
│ ←  通知                      │
├──────────────────────────────┤
│ この端末の通知      ✔ 許可済み│  ① OSの通知の状態
│ [ テスト通知を送る ]         │
├──────────────────────────────┤
│ 通知の種類                   │  ② 種類ごとのオン・オフ
│ 期限前のお知らせ      [ オン ]│
│ 期限超過のお知らせ    [ オン ]│
│ 毎朝のまとめ          [オフ ]│
├──────────────────────────────┤
│ 時刻                         │  ③ 時刻
│ 朝の通知時刻          9:00  ›│
│ 期限の初期時刻       18:00  ›│
├──────────────────────────────┤
│ 通知しない時間帯             │  ④ 通知しない時間帯
│ 使う                  [ オン ]│
│ 開始                 21:00  ›│
│ 終了                  7:00  ›│
└──────────────────────────────┘
```

### ① この端末の通知(N-04)
| 状態 | 表示 | 押すと |
|---|---|---|
| 許可済み | ✔ 許可済み | — |
| 未許可(まだ聞いていない) | ❗未設定 +「通知を許可する」ボタン | 理由を説明してから、OSの許可画面を出す |
| 拒否されている | ❗オフ +「設定の変え方」ボタン | OSの設定で許可する手順を、絵つきで表示 |
| iPhoneでホーム画面に追加していない | ❗追加が必要 +「追加方法」ボタン | ホーム画面への追加手順を表示 |

- 「テスト通知を送る」を押すと、数秒後に「テスト通知です。この通知が見えていれば設定は完了です」を送る。許可されていないときは押せない。
- 通知を送れない状態のとき、この画面の上部に赤い帯で「このままでは期限をお知らせできません」を表示する(N-04)。

### ② 通知の種類 (F-60)
| 種類 | 内容 | 初期値 |
|---|---|---|
| 期限前のお知らせ | カードごとに設定した時刻(前日・当日朝・1時間前)に送る | オン |
| 期限超過のお知らせ | 期限を過ぎて未完了のカードを、1回だけ送る | オン |
| 毎朝のまとめ(F-26) | 「朝の通知時刻」に、今日が期限と超過のカードの件数をまとめて送る | オフ |

- 「期限前のお知らせ」と「期限超過のお知らせ」をオフにするときは、「期限をお知らせできなくなります。オフにしますか」と確認する。
- 「毎朝のまとめ」は、該当のカードが0件の日は送らない。
- アーカイブしたボードのカードは、どの通知も送らない(S-02)。

### ③ 時刻 (F-62)
| 項目 | 内容 | 初期値 | 変えたときの動作 |
|---|---|---|---|
| 朝の通知時刻 | 「前日」「当日朝」の通知と、毎朝のまとめを送る時刻 | 9:00 | まだ送っていない通知の時刻を計算し直す。すでに過ぎた時刻になる通知は送らない |
| 期限の初期時刻 | 期限の日付を選んだとき、最初に入る時刻 | 18:00 | これから設定する期限だけに効く。すでにある期限は変わらない |

- 時刻はスマホ標準の時刻選択を使う。5分刻み。

### ④ 通知しない時間帯 (F-61)
- 「使う」がオンのとき、開始〜終了の間は通知を送らない。初期はオン、21:00〜7:00。
- 日をまたぐ設定(21:00〜7:00)に対応する。
- 時間帯に当たった通知は、終了時刻にまとめて送る。終了時刻にすでに期限が過ぎているものは、「超過」の通知としてまとめて送る。
- 開始と終了が同じ時刻のときは、「開始と終了は別の時刻にしてください」と表示して保存しない。
- 「朝の通知時刻」が通知しない時間帯に入っているときは、「朝の通知時刻が通知しない時間帯に入っています」と黄色の注意を出す(保存はできる)。

### 保存
- 変更したら、その場で自動保存する(「保存」ボタンは置かない)。
- 保存に失敗したら、元の値に戻して「保存できませんでした」と短く表示する。

## 4. S-06b 表示と演出

| 項目 | 内容 | 初期値 |
|---|---|---|
| 文字の大きさ | 標準(100%) / 大(125%) / 特大(150%) の3段階から選ぶ。選ぶとすぐ反映する | 標準 |
| 完了の演出 | チェックマークのアニメーションと振動のオン・オフ(F-71, N-16) | オン |

- 文字の大きさを選ぶ欄に、見本の文章を表示する。
- 特大(150%)を選んだときは、ボード画面を1リスト表示に切り替える(S-03)。選択肢の下に「ボード画面は1つずつのリスト表示になります」と表示する。
- iPhone のブラウザは振動を使えない。iPhone では、演出のオンのときもアニメーションだけを動かす。「完了の演出」の下に、iPhone のときだけ「この端末では振動は使えません」と小さく表示する。
- 端末の設定で「視差効果を減らす(動きを減らす)」がオンのときは、演出をオンにしていてもアニメーションを控えめにする。

## 5. S-06c 依頼先の管理 (F-35)

### 画面イメージ
```
┌──────────────────────────────┐
│ ←  依頼先の管理              │
├──────────────────────────────┤
│ 田中さん       未完了 3件  › │
│ 佐藤さん       未完了 0件  › │
│ 鈴木部長       未完了 1件  › │
└──────────────────────────────┘
```

| 操作 | 動作 |
|---|---|
| 行を押す | 名前の変更と削除を選ぶシートを出す |
| 名前を変更 | 1〜30文字。変えると、その人が担当のカード全てに反映する。同じ名前がすでにあるときは「その名前はすでにあります」と表示して変更しない |
| 削除 | 確認を出す。「田中さんを削除しますか。担当のカード3件は『担当者なし』になります」。削除すると候補から消え、担当のカードは担当者なしになる |
| 「自分」 | この一覧には出さない。名前を変えるときは、アカウント(S-06e)の表示名を変える |

- 依頼先が0件のとき、「依頼先はまだありません。カードの担当者に名前を入れると、ここに並びます」と表示する。
- 依頼先の追加は、カード詳細(S-04)の担当者選択で行う。

## 6. S-06d ごみ箱 (N-09)

### 内容
- 削除したカードを、削除が新しい順に並べる。
- 各行: タイトル / 元のボード名 / 削除した日 / 「あと○日」(30日で完全に消える)。

| 操作 | 動作 |
|---|---|
| 元に戻す | カードを元のリストに戻す。元のリストがアーカイブ済みのときは、そのボードの最初のリストに戻す。ボードがアーカイブ済みのときは、「ボードをアーカイブから戻してください」と表示して戻さない |
| 完全に削除 | 確認を出す。「完全に削除しますか。元に戻せません」。確認後に消す |

- 30日を過ぎたカードは自動で完全に削除する。
- 0件のとき、「削除したカードはありません」と表示する。
- 戻したカードの期限が過ぎているときは、超過として表示する。過去の通知は送り直さない。

## 7. S-06e アカウント

| 項目 | 操作 |
|---|---|
| 表示名 | 押すと変更できる(1〜30文字)。担当者の「自分」の名前も変わる |
| メールアドレス | 変更すると、新しいアドレスに確認メールを送る。メールのリンクを押すまでは、今のアドレスのまま |
| パスワード | 今のパスワードと、新しいパスワードを2回入力して変更する。条件は会員登録と同じ。変更したら他の端末のログインを解除する |
| ログアウト | 設定の一覧と同じ |
| 退会(アカウントの削除)(F-03) | 下記 |

### 退会
1. 「退会する」を押す。
2. 「退会すると、全てのボード、カード、実績が削除され、元に戻せません。先にデータを書き出すことをおすすめします」と表示する。「データを書き出す」ボタンを並べる。
3. パスワードを入力して「退会する」を押す。
4. 全データを直ちに削除し、バックアップからも30日以内に削除する。ログアウトして、ログイン画面へ戻る。「退会しました」と表示する。

- パスワードが違うときは退会できない。

## 8. データを書き出す (F-83, UC-08)

### 流れ
1. 「データを書き出す」を押す。
2. 形式を選ぶ。

| 形式 | 内容 | 用途 |
|---|---|---|
| 全データ(JSON) | ボード、リスト、カード、チェックリスト、メモ、履歴、ラベル、依頼先、設定 | 控え、機種変更 |
| カード一覧(CSV) | カード1枚を1行にした表(ボード名、リスト名、タイトル、担当者、期限、完了日時、期限内か) | 表計算ソフトで見る |

3. 「書き出す」を押すと、ファイルを作り、スマホの保存・共有の画面を開く。
4. 保存が済むと「書き出しました」と表示する。

### 規則
- ファイル名は `task-management-YYYYMMDD` に拡張子を付ける(例: `task-management-20261027.json`)。
- パスワードなど、ログインに関わる情報は含めない。
- ごみ箱の中のカードは含めない。
- 通信できないときは「通信できません。電波の良い場所でお試しください」と表示する。
- 作成に時間がかかるときは「作成中…」を表示する。失敗したら「作成できませんでした [もう一度試す]」。

## 9. 状態ごとの表示(共通)

| 状態 | 表示 |
|---|---|
| 読み込み中 | 項目の形をした灰色の枠(スケルトン) |
| 読み込み失敗 | 「読み込めませんでした」+「もう一度試す」 |
| オフライン | 画面上部に「通信できません」を表示。設定の変更は端末に保存し、復帰後に反映する。データの書き出しと退会、パスワード変更は押せない |

## 10. 見やすさ・操作性
- 設定の1行の高さは 56px 以上。オン・オフのスイッチは 44×44px 以上で、「オン」「オフ」の文字も添える(色だけに頼らない)。
- 文字は 16px 以上。設定の文字サイズに従う。
- 戻る操作は、画面左上の ← と、スマホの戻る操作の両方で行える。
- 取り返しのつかない操作(完全に削除、退会)は、必ず確認を挟み、ボタンの色を赤にする。

## 11. この画面で使うデータ
[ER図](er-diagram.md) の `user_settings`、`push_subscriptions`、`assignees`、`cards`(`deleted_at` を使うごみ箱)、`users`。書き出しは全テーブル。
